# [이상한 체스](https://www.codetree.ai/frequent-problems/samsung-sw/problems/odd-chess)

**SW 역량 테스트** › 2018 상반기 오전 1번 문제

개인코드리뷰 <br/>
260825 이상한체스

코드길이: 주석 포함 180줄 <br/>
메모리: 21MB <br/>
수행시간: 129ms

문제이해 및 구상 (25분) <br/>
구현(70분) <br/>
구현 중 구상이 잘못되었음을 깨달았으나 시간 관계상 엎지 못함. <br/>
야자 시간에 재구현 후 문제 제출 -> 성공

**[문제이해 및 구상]**
- 루틴 대로 문제를 꼼꼼히 읽지 못했음. 루틴을 지키지 않을 거면 뭐하러 루틴을 만드는지?
- 백트래킹을 활용하여 각 말이 향할 방향을 골라야겠다는 구상만 구체적으로 하고 말들의 이동은 구체적으로 구상 안함.
- 말의 이동을 구상할 때 bfs로 하면 되겠다고 생각하고 얼렁뚱땅 넘어감.
- 혹시나 백트래킹을 하다가 시간초과가 나지는 않을까 노심초사했는데 시간복잡도 계산을 잘못한듯. 걱정할 부분이 아니었음.

**[구현]**
- 말의 방향을 뽑는 것까지는 10분 이내 정도의 시간으로 굉장히 빠르게 구현 완료함.
- 그러나 말이 이동할 수 있는 곳에 표시를 하는 부분을 구현할 때 bfs로 아무 생각 없이 구현했다가
- 평소 bfs 구현하던 방식으로 하면 말들이 정해진 방향으로 가지 않고 갈 수 있는 곳을 다 가버린다는 걸 깨달음.
- 따라서 말들이 정해진 방향으로만 끝까지 가도록 다시 구현을 해야했는데 bfs 구현 말고는 생각을 안해둔 상황에서
- 갈아엎으려니 자꾸 bfs를 버리질 못했고 결국 어떻게 구현해야 할지 감이 왔을 때는 문제 풀이 시간이 끝나기 10분 전이었음,
- 간단한 구현인데 왜 시간 안에 못했을까..?

**[재구현]**
- 말들을 이동시킬 때 어떻게 하면 코드를 간결하면서도 반복적인 부분 없이 짤 수 있을까 생각하다가 포기하고
- 그냥 내가 편한 대로 짬. 시험 시간에도 그냥 구현하기 편한 방식으로 할 걸이라고 후회했음.
- 그리고 오픈테케 돌리면서 문제 조건도 빼먹었다는 걸 깨달음. 개판이다.

**[잘한 점]**
- 디버깅용 프린트 함수를 만든 것.
- 시간복잡도를 고민하긴 한 것.

**[못한 점]**
- 어제부터 체감하는 건데 나는 bfs가 어떤 역할을 하는 알고리즘인지 충분히 생각을 하지 않고 bfs로 하면 되겠지 하는 방만한 판단을 함.
- 제발 격자만 보면 bfs로 풀어야지라고 생각 좀 하지말자.
- 문제도 충분히 꼼꼼하게 읽지 못했음. "'비어있음에도' 자신의 말을 이용해서 갈 수 없는"
- 그렇게 어려운 문제도 아니었는데.. 여러모로 아쉬움이 남는다.
- 몸이 안 좋을 수록 더 차분하고 침착하게 풀자.
