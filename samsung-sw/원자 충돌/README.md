# [원자 충돌](https://www.codetree.ai/frequent-problems/samsung-sw/problems/atom-collision)

**SW 역량 테스트** › 2020 하반기 오전 2번 문제

개인코드리뷰 <br/>
260821 원자충돌

코드길이:주석 포함 90줄 <br/>
메모리: 32MB <br/>
수행시간: 369ms

문제이해 및 구상 (20분) <br/>
구현 (40분) <br/>
오픈 테케 돌려봄 -> 성공 <br/>
검증 (5분) <br/>
문제 제출 -> 성공

**[문제이해 및 구상]**
- 문제들을 받았을 때 조금씩 살펴보며 이게 시뮬레이션 문제라는 것을 알고 맨 마지막에 풀기로 함.
- 그런데 2시간 정도가 넘어가니 집중력이 바닥나기 시작해서 평소처럼 문제를 몇 번씩 읽고 꼼꼼하게 보자는 마음가짐이 안 잡힘.
- 대신 성급하게만 하지 말자라고 생각했음.
- 한참 고민한 것은 원자들을 어떻게 관리할 것인가라는 부분.
- 같은 위치에 있는 애들을 한 번에 처리를 해주기도 해야 하고 동시에 애들을 다 돌면서 위치 이동도 시켜주어야 한다는 점에서
  어떤 자료구조로 뭘 활용하여 관리해주어야 할지 고민스러웠음.
- 고민 끝에 위치 이동은 큐, 원자 합성은 3차원 배열을 활용하기로 결정하고 구현 시작.
- 대충 코드 흐름을 그림 블록으로 그리고 어디서 변수 및 배열 선언할지 등만 간략히 그리고 시작함.

**[구현]**
- 3차원 배열을 잘 안 쓰다보니까 선언부터 값 넣기, 읽어오기 등등의 코드에 자신이 없었음.
- 따라서 간단한 코드를 중간중간 짜보면서 코드가 맞는지 점검하는 시간을 가지느라 구현이 더뎠음.
- 새로운 원자의 질량 및 속력을 담는 변수를 선언할 때 초기값으로 -1을 넣는 알 수 없는 사고를 함.
- 구현 다 하고 점검하다가 이상해서 고치기는 했지만 오픈테케에서 티가 안 나는 부분이었음. 주의하자.
- 요새 무의식적으로 하는 것 같은데 기능 하나 완성하면 그 부분이 잘 돌아가는지 찍어보며 확인함.

**[검증]**
- 늘 하는 것은 예시 같은 게 주어지면 내 코드의 과정을 다 print 찍어보면서 토씨 하나 틀린 것이 없고 흐름에서 빠진 것이 없는지 보는 것인데
- 이 방법으로 꽤나 실수도 금방 찾고 정확도가 높아지는 것 같음.
- 그런데 솔직히 이 문제를 다 풀었을 때 즈음에는 체력이 바닥나서 더 꼼꼼한 점검을 하지 못함.
- 이런 문제는 엣지 케이스나 내 코드가 놓쳤을 만한 케이스를 어떻게 만들어야 하는지 감도 안 옴.
- 따라서 한 번에 맞기는 했지만 운이 좋았다는 생각만 든다.

성공.

**[잘한 점]**
- 격자 연결 같은 조건은 비슷한 걸 많이 풀어봐서 이제 익숙하게 코드를 짠다.
- 변수 초기화 잘못한 것을 검증할 때 찾아낸 것.

**[못한 점]**
- 솔직히 코드가 완벽히 맞는지 자신이 없는데 체력이 떨어져서 그냥 제출했음.
- 힘들다고 이렇게 막 내면 안된다고 생각함.
- 오늘은 운이 좋았지만 테케 만들기 등을 연습해서 검증 시간 더 가져가자.
- 아직까지는 문제들이 간단한 편이지만 더 어려워지면 손설계 더 길게 해야할 것 같음. 지금 너무 구상 대충함.
