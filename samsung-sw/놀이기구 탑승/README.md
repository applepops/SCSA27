# [놀이기구 탑승](https://www.codetree.ai/frequent-problems/samsung-sw/problems/go-on-the-rides)

**SW 역량 테스트** › 2021 상반기 오전 1번 문제

개인코드리뷰 <br/>
260821 놀이기구탑승

코드길이: 주석 포함  <br/>
메모리: 16MB <br/>
수행시간: 49ms

문제이해 및 구상 (15분) <br/>
구현 (30분) <br/>
오픈테케 돌려봄 -> 성공 <br/>
문제 제출 -> 성공

**[문제이해 및 구상]**
- 순서가 명확히 나누어져있는 문제라고 느껴서 문제에서 제시된 그대로 순서대로 처리만 하면 되겠다고 생각.
- 학생들과 학생들이 선호하는 친구들은 list index를 이용해서 관리하기로 결정. 딕셔너리 쓸까 고민했지만 이 경우는 학생 num 때문에 리스트가 유리하지 않을까.
- 손설계로 코드 블럭 그리고 나서 이렇게 문제에서 주는 그대로만 따라가도 되는 걸가 (더 연산을 줄이거나 하는 방법 없을까) 라는 생각을 잠시 함.
- 그런데 괜히 그렇게 했다가 꼬이면 화날 것 같아서 안전빵으로 가기로 함.

**[구현]**
- 기능 단위로 만들고 난 뒤에 예상한 대로 동작하는지 찍어보는 루틴을 지켰음.
- 이 과정에서 두 가지 정도의 작은 오류들을 발견.
- 1) 빈자리 확인할 때 자꾸 != 0으로 작성한다는 것. 벌써 기출에서 2번 한 실수.
- 2) 위치마다 좋아하는 친구 수 세는 배열 초기화를 0으로 한 것. 값이 0이 될 가능성이 충분히 있기 때문에 논리적으로 잘못된 초기화. -1로 수정.
- 하지만 오류를 잡아내는 과정이 약 5분 정도로 그리 길지는 않았음.

**[검증]**
- 첫 문제 및 이번 문제가 난이도가 어렵게 느껴지지 않았던 것에 비해 시간을 꽤 쓴 것 같아서
- 마음이 급해져서 테스트케이스를 만들거나 하지 않고 오픈 테케만 돌려보고 제출함.
- 그런데 학생 번호도 그렇고 안전한 제한 조건들로 주어진 문제라서 엣지케이스는 지금 생각해도 잘 모르겠음.

성공.

**[잘한 점]**
- 구현 중 기능 검사에서 두 가지의 실수를 모두 미리 찾아낸 것.

**[못한 점]**
- 마음이 알게 모르게 무의식적으로 급했던 것.
- 다른 사람들은 알 바냐? 하면서 나의 페이스대로 갈 필요가 있음.
