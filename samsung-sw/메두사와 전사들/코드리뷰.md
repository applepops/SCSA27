개인코드리뷰 <br/>
260922 메두사와 전사들

코드길이: 주석 포함 약 300줄 <br/>
메모리: 31MB <br/>
수행시간: 1193ms
 
문제이해 및 구상 (53분) <br/>
구현 (120분 이상) <br/> 
오픈테케 -> 2번 틀림 <br/>
디버깅 (60분) <br/>
제출 -> 성공

**[문제이해 및 구상]**
- 으악 할 게 너무 많고 복잡하고 구현량도 많은 문제. 압도 당해버렸다.
- 평소처럼 문제이해까지는 손설계로 하다가 시간이 너무 많이 지났길래
- 이대로 하면 구현도 다 못해보고 끝나겠다 생각, Ideation 안하고 당당하게 구현 들어감.
- 루틴을 지키지 못했는데 이런 비상 사태일 때 어떻게 할지 고민스럽다.
- 처음에 메두사 바라보는 곳들이나 전사들이 가리는 좌표 어떻게 할지 모르겠었는데
- 구현 도중에 생각남.

**[구현]**
- 경로 찾는 bfs는 저번에 해봐서 금방 구현했고
- 그 외에 메두사가 쳐다보는 것 구하는 것까지 쉬웠는데
- 전사들이 가리는 곳 찾는 게 하드코딩말고는 모르겠어서 시간 많이 씀.
- 그외에도 in으로 하나하나 좌표 있나 없나 확인하니까 최대 300명의 전사가 있다보니
- 시간이 터지지는 않을까 우려되었는데 일단 시간없어서 진행함.
- 또한, 오랜만에 set을 썼는데 set union함수가 죽어도 적용이 안되는 것임.
- 아직도 뭐가 잘못됐는지 모르겠어서 결국 list로 합치고 set으로 바꾸는 방식을 선택함.
- 처음부터 이렇게 할 걸 괜히 이것 저것 해보다가 30분은 넘게 쓴 것 같음.

**[디버깅]**
- 오픈테케 1번까지는 맞았는데 2번이 틀림. 전사가 돌이 되는 사람이 2명이어야 하는데 3명 나옴.
- 어디서 문제가 있는 건지 싸한 부분을 잘 모르겠고 조건도 딱히 틀린 건 없는 것 같아서
- 그냥 print문으로 다 찍어보기로 하고 문제의 부분을 보니까
- for문에서 뒤로 가게 할 때 (:-1:-1) 이렇게 써야 하는데 또 (:0:-1) 이렇게 써서 끝까지 안 간 거였음.
- 진짜 돌아버리겠다. 이것때문에 시간 안에 못 푼 거라니 믿을 수가 없다.

성공.

**[잘한 점]**
- 1트에 성공.

**[못한 점]**
- for문 저거 가끔 실수하는 건데 진짜 잘 보이지도 않고 잘 의심도 안 가고 미치겠다.
- 어제오늘 문제가 당황스럽고 어려우니까 루틴을 안 지키는데 뭐하고 있는 건지 모르겠다.
- 근데 손설계 하던 습관 때문에 조건을 자꾸 안 놓치려고 해서 로직 실수가 덜한 건가..?
- 시간 안에는 못 풀지만 자꾸 1트만에 성공하긴 함.
- 이번 주는 틀린 게 로직이 아니고 다 index거나 range임.
