개인코드리뷰 <br/>
260901 술래잡기 체스

코드길이: 약 110줄  <br/>
메모리: 16MB  <br/>
수행시간: 51ms

문제이해 및 구상 (30분)  <br/>
구현 (60분)  <br/>
1차 제출 -> 실패  <br/>
디버깅 (20분)  <br/>
2차 제출 -> 성공

**[문제이해 및 구상]**
- 술래말이 얻을 수 있는 최댓값을 얻어야 하니 백트래킹 문제라고 판단.
- 도둑말들의 위치를 O(1)로 알 수 있도록 리스트 하나와 전체를 알 수 있는 3차원 배열 구상.
- 도둑말이 45도씩 돌다가 갈 곳을 못 찾으면 본인 방향으로 돌아오도록 총 8번 돌도록 설계.

**[구현]**
- 무슨 정신으로 했는지 모르겠음. 기억이 흐릿함.
- 다 하고 보니 엉망이었고 우연의 일치로 오픈 테케는 다 맞았지만 인덱스 에러가 남.
- 단순한 실수라기 보다는 치명적인 논리적인 오류가 있다고 느껴져서 디버깅을 반쯤 포기함.
- 도둑말들의 이동을 원상복귀 시키는 게 불가하니 깊은 복사를 해서 넘겨야 했는데 이것도 미리 설계하고 들어간 게 아니고
- 즉흥적으로 하다보니 너무 헷갈렸음.

실패.

**[재구현]**
- 디버깅은 어렵다고 판단, 재구현을 결심.
- 문제를 다시 차분히 읽으며 빠진 조건들을 채워넣었더니 잘 돌아감.

성공.

**[잘한 점]**
- 딱히 없음.

**[못한 점]**
- 초반에 집중력이 떨어져서 구상도 꼼꼼히 못하고 구현도 얼이 빠진 채로 함.
- 백트래킹에서 가장 중요한 종료조건이 명확하지 않은 문제라 코드 짤 때 자신이 없었음. (종료조건에서 출력을 뽑아본다거나 하는 게 판단이 어려워서)
- 실제로도 '술래말이 잡을 말이 없는 곳으로는 이동할 수 없다'는 조건을 빠뜨려서 인덱스 에러가 나기도 했음.
- 백트래킹을 디버깅하는 것은 너무 어렵다고 생각해서 문제풀이 시간에 디버깅도 열심히 못했다. -> 차라리 문제를 다시 읽었어야 했다.
