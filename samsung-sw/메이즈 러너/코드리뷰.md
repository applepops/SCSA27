**[문제이해 및 구상]**
- 1. 멘허튼 거리로 움직이는 사람들의 처리
- 2. 정사각형 찾기
- 이렇게 두 가지가 좀 어렵게 느껴졌음.
- 멘허튼 거리는 처음에 bfs로 접근해야 하나 싶었는데 단순 계산으로 가능했음.
- 그런데 조건문 나열 외에는 스마트한 방법이 생각 안 나서 그냥 기세로 가기로.
- 그리고 문제의 정사각형 찾기는 exit혹은 사람이 꼭짓점이 되어 정사각형을 아루게 되는
- 경우의 수만 생각하고 꼭짓점 찾기로 로직을 짜버림.

**[구현]**
- 80%정도 다 구현을 하고 나서 정사각형 찾기 단위테스트를 해보다가
- 논리에 치명적인 문제가 있다는 것을 발견.
- 0 H 0 <br/>
  0 0 0 <br/>
  0 E 0
- 위의 경우 둘 다 꼭짓점이 아님.
- 그래서 패닉에 빠져서 당황하다가 다시 생각을 해야겠다고 생각함.

**[재구상]**
- 완탐으로 정사각형을 찾기로 결심.
- 이게 제일 쉽고 구현도 쉬운 방법이었다는 게 재밌는 포인트.

**[재구현]**
- 다시 구현하기 시작.
- 그런데 놀랍게도 손설계때 인간들을 돌리는 걸 아예 빼먹어버렸다는 걸
- 알게 되었는데 시간이 40분안팎밖에 없어서 설계 건너 뛰고
- 즉흥적으로 코드 짜기 시작. 마음이 굉장히 급했다.
- 처음에는 인덱스 계산을 하고 싶었는데 한참을 들여다봐도 규칙을 찾는 게
- 너무 어렵고 나는 늘 돌리는 건 zip으로 돌려왔기에
- 다시 급하게 3차원 인간 정보 arr을 만들었음.
- 그 와중에 3차원 deep copy 하는 법 몰라서 또 헤맴.
- 새로운 자료구조가 또 생겨버렸으니 갱신주의하자고 생각한 뒤
- 예시의 경우 라운드마다 찍어보고 되길래 9분 남기고 제출.
