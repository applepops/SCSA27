개인코드리뷰 <br/>
260903 윷놀이 사기단

문제이해 및 구상 (60분) <br/>
구현 (30분) <br/>
오픈테케 -> 실패 <br/>
1차 디버깅 (80분) <br/>
2차 디버깅 (60분)

**[문제이해 및 구상]**
- 말놀이판을 어떻게 구현할 것인가 고민스러웠음.
- 결국 내가 생각할 수 있는 가장 간단한 방법인 큰 줄기 4개를 만들어서 분기 지점을 만나면 갈아타게 해야겠다고 생각함.
- 그러나 이건 말놀이판의 숫자들을 충분히 고려하지 못하고 한 판단이었고, 같은 숫자가 여러 개 있다는 것을 (특히 30) 발견하지 못하고 넘어감.
- 그 외에는 백트래킹인 것 같아서 디버깅이 어려우니 정신 똑바로 차려야겠다고 생각함.

**[구현]**
- 구현 자체는 어려운 게 특별히 없었음.
- 그런데 오픈테케 1번부터 안 나오니 정말 당황스러웠음.

**[1차 디버깅]**
- 남은 시간을 내내 쳐다보고 있었고 들어가는 말들을 확인해보니 같은 숫자 자리에 자꾸 말들이 들어감.
- 처음에는 복사가 잘못되고 있나 싶어 넘기는 리스트 이름을 수정했음.
- 그리고 문제도 여러 차례 다시 읽어서 같은 숫자인데 다른 라인에 있는 경우를 찾아냄.
- 그러나 여기서 더욱 문제를 발견하지 못하고 시간 끝남.

**[2차 디버깅]**
- 1차 디버깅 때는 문제의 글만 읽어서 찾아내지 못했는데
- 말놀이판의 숫자들을 더욱 유심히 살펴보니 내 로직을 뚫어버리는 30이라는 숫자와
- 줄기들이 공유하고 있는 숫자인 25, 35, 40과 같은 숫자들을 발견함.
- 필요한 분기문 추가하고 안되면 또 들어가는 말 리스트 찍어보면서 어떤 게 다른지 확인함.

**[잘한 점]**
- 특별히 없음.

**[못한 점]**
- 솔직히 이 문제는 시간이 훨씬 더 있었어도 못 풀었을 것 같음.
- 나는 처음에 내가 백트래킹 코드를 잘못 짰구나 생각했는데
- 늘 그렇듯 안되는 것은 제대로 조건을 보지 않았고 문제를 성실히 반영하지 않아서인 것.
- 그래도 그림의 숫자들을 유심히 들여봐야했던 이번 문제는 다시 풀어도 풀 수 있을까 싶을 정도로 절망스러움.
- 그런데 어쩌겠냐. 매일매일 문제를 제대로 읽자 받아들이자 애쓰는데 맨날 같은 걸로 코드리뷰를 쓴다.
