# [테트리스 블럭 안의 합 최대화 하기](https://www.codetree.ai/frequent-problems/samsung-sw/problems/max-sum-of-tetris-block)

260819 테트리스 블럭 안의 합 최대화하기

코드길이: 주석 포함해서 약 300줄; <br/>
메모리: 21MB <br/>

14:35 ~ 14:50 문제이해 및 구상 <br/>

**[문제이해 및 구상]**
- 회전 및 뒤집기가 가능하다는 걸 보고 모양을 하나라도 놓치면 대참사가 나겠구나 싶어서 정신 차리자 싶었음.
- arr가 최소 4*4이기 때문에 일단 모든 모양이 다 들어갈 수는 있으리라 판단.
- 스마트한 방법이 정녕 없는 것일까 고민하다가 모르겠어서 기세로 하드코딩하고 완탐하자고 생각함. 현타 왔음.
- 모든 칸마다 19가지의 방법을 다 해보자고 결심.
- 바로 구현 들어가면 100% 좌표 실수할 것 같아서 좌표까지 미리 다 적어두고 구현 시작함.

**[구현]**
- 모든 모양마다 함수를 만들었음.
- 함수 이름은 모양마다 알파벳 붙이고 모양이 달라질 때마다 뒤에 숫자 붙여서 구분함.
- 종이에 적어둔 걸 그대로 옮기는데도 중간에 중복으로 작성해서 철렁했으나 정신을 붙잡고 차근차근 다시 작성.
- 복붙하다가 다 안 고쳐서 실수를 한 적이 과거에 상당히 많았기 때문에 신경써서 한 줄 한 줄 보려고 했음.

성공

**[잘한 점]**
- 미리 좌표를 다 써둔 것을 잘했다고 생각함. 코드 짜면서 좌표 계산했으면 분명 길을 잃었을 것.

**[못한 점]**
- 굳이 일일이 함수를 만들 필요가 있었나 싶다. 상당히 부끄럽다.
- 근데 또 하나의 거대한 배열에 좌표들을 때려넣었으면 하다가 길 잃은 어린 양이 되었을 것 같기도 하다.
- 코드가 길어지더라도 차라리 실수를 하지 않는 안전한 방법이 나을지도 모른다.
- 그리고 이걸 하드코딩이 아닌 다른 방법으로 풀 수 있는 방법을 내가 다시 풀어도 떠올릴 수 있을까 싶다.
