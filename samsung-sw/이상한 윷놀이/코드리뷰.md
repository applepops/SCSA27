개인코드리뷰 <br/>
260901 이상한 윷놀이

코드길이: 주석 포함 약 160줄 <br/>
메모리: 17MB <br/>
수행시간: 97ms

문제이해 및 구상 (25분) <br/>
구현 (35분) <br/>
오픈테케 -> 실패 <br/>
디버깅 (35분) <br/>
제출 -> 성공

**[문제이해 및 구상]**
- 말들의 위치를 바로 꺼내올 수 있는 2차원 리스트와 말들의 판 위치를 가시적으로 볼 수 있는 3차원 리스트
- 두 개를 운용해야겠다고 판단.
- 그러나 전에도 이렇게 자료구조를 여러 개 사용하면 꼭 실수를 해서 불안했음.
- '만약 중간에 말이 4개 이상 겹치면 즉시 게임 종료'에 주의하려고 함.
- 언제든 끝날 수 있으니 주의하자라고 생각하고 들어갔는데도 구현하다가 잊어버림. 바보 아냐?

**[구현]**
- 실수를 여러 개 함.
- 1. 색깔 확인용 array와 말들이 있는 array를 헷갈려서 이상한 if문으로 확인을 하느라 제대로 코드가 안 돌아감.
- 2. 여러 말을 등에 지고 있는 말의 위치를 옮길 때 그 말의 위치만 옮기고 위에 올라탄 애들은 안 옮겨줌.
- 예시로 준 것이 별로 없었기 때문에 예시 테케를 돌려가며 최대한 문9제를 찾아내려 함.

실패.

**[디버깅]**
- 예시 테케만 보면 하얀색의 경우 파란색의 경우 빨간색의 경우 모두 다 잘 처리되는 것을 보았는데
- 어째서 답은 나오지 않는가 미궁 속으로 빠졌음.
- 그래서 손설계를 한 종이를 멍하게 쳐다보다본니 말이 중간에 4개 이상 겹치면 즉시 종료라는 말을 보고 눈물을 흘릴 뻔.
- 전의 구현은 모든 말의 이동이 끝나고만 check를 하고 있었던 것임.
- 이것을 한 말의 이동이 끝나고 check로 바꿔서 제출하여 성공.

성공.

**[잘한 점]**
- 예시 테케 돌려가며 찍어본 것.
- 차분하게 논리적인 문제점을 찾아낸 것.
- 틀린 이유를 모르겠을 때 손설계 종이와 문제를 다시 살펴본 것.

**[못한 점]**
- 어느 정도 아이디어만 떠오르면 구현으로 바로 들어가서 한참을 디버깅에 시간을 쓰는 것.
- 문제에서 주의해야하는 부분을 알고 있었음에도 실수한 것.(과거에도 유사한 실수한 적 있음)
