260904 술래잡기

문제이해 및 구상 (25분) <br/>
구현(75분) <br/>
1차 제출 -> 런타임 에러 <br/>
디버깅(2분) <br/>
2차 제출 -> 성공

**[문제이해 및 구상]**
- 달팽이 구현 부분을 보고 문제가 싫어졌다.
- 하지만 계속 싫어만할 수는 없었기에 애정을 가지고 보려고 노력했다.
- 아쉬운 점은 시간이 많이 없다는 생각이 들어서 급한 마음에 구상을 짧게 한 것.
- 이번에는 다행히 문제를 잘못 읽거나 로직의 큰 실수 같은 건 없었지만 루틴을 지켜야 한다고 생각함.
- 달팽이 부분을 구현 시도해보다가 도저히 방향과 좌표를 같이는 못하겠어서 포기하고 따로따로 배열을 만들기로 함.
  
**[구현]**
- 달팽이 부분 구현에 거의 40분 이상은 쓴 것 같음.
- 중심부분과 0,0은 한 번씩만 가야하고 방향과 좌표가 각각 규칙이 따로 놀기 때문에 상당히 다루기 까다로웠음.
- 따라서 그렇게 깔끔하지는 않은 더티 코드가 완성됨.
- 달팽이 구현하느라 시간을 많이 써서 뒷부분에서 상당히 급하게 코드를 짰고 따라서 분기문이나 조건문이 난리법석임.
- 구상때까지만 해도 기억하고 있었던 인덱스 부분을 마지막에 생각 못하고 급하게 제출하는 바람에 인덱스 에러남.

실패.

**[디버깅]**
- 다행히 어디서 런타임 에러가 났는지 바로 알아차렸고 버그 잡음.

성공.

**[잘한 점]**
- 문제를 미워할 뻔했지만 참은 것.

**[못한 점]**
- 마음이 너무 조급해서 충분히 예방할 수 있었던 런타임 에러가 난 것.
- 마음을 그렇게 급하게 먹지 않아도 충분히 풀 수 있는데 괜히 옆사람보다 빨리 나가겠다는 경쟁심에 불타오름.
- 반성합니다.
